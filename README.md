# КлассТест — Полноценная система онлайн-тестирования для школьников

Надёжное real-time веб-приложение для одновременного тестирования в классе минимум **37+ учеников** (с поддержкой до **50 учеников**) и одного учителя.

---

## 🎯 Ключевые возможности

1. **Строгое распределение 50 уникальных бланков**:
   - Атомарная выдача ID на сервере через транзакции базы данных.
   - Фиксированное соответствие: `student_id = N` → `form_id = N` (ID 1 → Бланк 1, ID 17 → Бланк 17, ID 50 → Бланк 50).
   - Лимит: ровно 50 доступных мест. При переполнении: *"Все доступные места заняты."*
2. **Структура теста из 30 вопросов (20 минут)**:
   - **Вопросы 1–20**: одиночный выбор одного правильного ответа из 4 вариантов (A, B, C, D).
   - **Вопросы 21–30**: самостоятельный свободный ввод ответа (числа, обыкновенные дроби `1/2`, десятичные дроби `0.5` или `0,5`, выражения).
   - Переходный экран перед вопросом 21: *"Вторая часть теста. Вопросы 21–30 требуют самостоятельного ввода ответа."*
3. **Безопасная математическая проверка (БЕЗ `eval`)**:
   - Математический парсер эквивалентности: понимает `1/2 == 0.5 == 0,5 == 2/4 == 3/6`.
   - Поддержка отрицательных чисел, безопасных арифметических вычислений.
4. **Математическая типографика (KaTeX)**:
   - Дроби ($\frac{a}{b}$, $\frac{x+2}{x-3}$), степени ($x^2$, $2^5$), корни ($\sqrt{64}$), индексы ($x_1$), уравнения ($2x+6=14$) и неравенства.
   - Адаптивный рендеринг без горизонтального скролла на мобильных устройствах.
5. **Mobile-First интерфейс**:
   - Проверено на 6 размерах экранов: `320×568`, `360×800`, `375×812`, `390×844`, `412×915`, `430×932`.
   - Крупные touch-области (кнопки от 48px до 58px).
6. **Надёжная синхронизация и защита от списывания**:
   - Таймер контролируется сервером (`started_at`, `ends_at`) с монотонным таймером `performance.now()` (изменение часов телефона не влияет на тест).
   - Фиксация событий: `visibilitychange` (сворачивание вкладки), `pagehide`, `fullscreenchange`, разрыв соединения.
   - Результат и баллы **скрыты** до завершения теста и рассчитываются **только на сервере**.
   - Пятибалльная система: 90–100% → **5**, 75–89% → **4**, 50–74% → **3**, 0–49% → **2**.
   - Сохранение сессии: при обновлении страницы или разрыве связи на 5 секунд ученик возвращается к тому же ID и бланку без потери прогресса.
7. **Генерация официальной Excel-ведомости (.xlsx)**:
   - В дашборде учителя доступно скачивание полноценной Excel-таблицы.
   - Содержит: **Фамилию, Имя, Оценку, Баллы, Процент, Номер бланка, ID, Статус сдачи, Точную дату и время сдачи, а также Дату и время проведения всего тестирования**.
   - Автоматический расчёт среднего балла и средней оценки по классу, цветовая подсветка оценок (5 — зелёный, 4 — синий, 3 — жёлтый, 2 — красный).

## 🏗 Архитектура и стек технологий

- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS, KaTeX, Lucide Icons, Socket.IO Client.
- **Backend**: Node.js, Express, TypeScript, Socket.IO, PostgreSQL (через `pg` или встроенный zero-config движок `@electric-sql/pglite` для локального запуска).
- **База данных**: Реляционная схема PostgreSQL (`games`, `forms`, `questions`, `answer_options`, `form_questions`, `students`, `student_answers`, `game_events`).
- **Тестирование**: Vitest (юнит-тесты и тест конкурентности), Playwright (E2E и Mobile UX), скрипт нагрузочного тестирования на 37 виртуальных учеников.

## 🚀 Быстрый старт (Локальная разработка)

### 1. Установка зависимостей
Требуется Node.js v20+ или v22+:
```bash
npm install
```

### 2. Настройка окружения
Скопируйте шаблон `.env.example` в `.env`:
```bash
cp .env.example .env
```
По умолчанию `DATABASE_URL` можно оставить пустым — приложение автоматически использует встроенный PostgreSQL движок `pglite`, сохраняющий данные в локальной папке `.pgdata`.

Для подключения к внешнему серверу PostgreSQL укажите:
```env
DATABASE_URL=postgresql://postgres:password@localhost:5432/classroom_test
```

### 3. Выполнение миграций и загрузка seed данных
Генерирует все **50 бланков** по **30 вопросов** (всего 1500 заданий):
```bash
npm run migrate
npm run seed
```

### 4. Запуск в режиме разработки
Запуск backend (порт `3001`) и frontend (порт `3000`):
```bash
npm run dev
```
Откройте браузер по адресу: `http://localhost:3000`

## 🧪 Запуск тестов

### Юнит-тесты и тесты конкурентности (Vitest)
Проверяет математический парсер, эквивалентность дробей/чисел, 5-балльную шкалу оценок и параллельный вход 37 учеников без дублирования ID:
```bash
npm run test
```

### Нагрузочное тестирование (37 одновременных учеников)
Симулирует полный жизненный цикл: 37 виртуальных учеников параллельно подключаются по WebSocket, получают ID 1..37 и бланки 1..37, дожидаются старта, отправляют **1110 ответов** (37 × 30) и завершают тест. Проверяет **0 потерянных ответов** и 100% корректность расчёта баллов:
```bash
npm run test:load
```

### E2E и проверка Mobile UX (Playwright)
Проверяет отображение без горизонтального скролла, сенсорные элементы и формулы KaTeX на всех 6 мобильных экранах (`320×568`, `360×800`, `375×812`, `390×844`, `412×915`, `430×932`):
```bash
npm run test:e2e
```

## ☁️ Развёртывание на Render (Single Web Service)

Проект полностью оптимизирован для запуска на платформе **Render** в виде **одного Web Service** (один публичный URL вида `https://my-test.onrender.com`), объединяющего:
* Express REST API
* Real-time WebSocket / Socket.IO
* Отдачу скомпилированного React SPA-фронтенда
* Автоматический запуск миграций и seed (50 бланков × 30 вопросов) при первом старте

### Способ 1: Автоматический деплой через Render Blueprint (Рекомендуется)
1. Загрузите репозиторий на GitHub / GitLab.
2. В панели управления Render выберите **New +** → **Blueprint**.
3. Подключите ваш репозиторий. Render автоматически считает файл `render.yaml`, создаст:
   - Базу данных **PostgreSQL** (`classtest-db`)
   - Сервис **Web Service** (`classtest-app`) с привязанными переменными окружения.
4. Нажмите **Apply**. После сборки приложение будет доступно по вашему Render URL!

### Способ 2: Ручная настройка Web Service
1. В панели Render создайте **New +** → **PostgreSQL** (если хотите использовать облачную базу). Скопируйте `Internal Database URL`.
2. Создайте **New +** → **Web Service**:
   - **Environment**: `Node`
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm start`
   - **Health Check Path**: `/health`
3. В разделе **Environment Variables** добавьте:
   - `NODE_ENV` = `production`
   - `DATABASE_URL` = `<ваш Internal Database URL>` *(если не указывать, приложение запустится на встроенном движке PGlite)*
   - `SESSION_SECRET` = `<случайная строка>`
   *(Переменная `PORT` задаётся платформой Render автоматически).*
4. Нажмите **Deploy**.

## 📋 Формат импорта реальных вопросов (JSON)

Вы можете загрузить свои варианты бланков через панель учителя («Управление бланками и импорт») или POST-запрос на `/api/import/form`:

```json
{
  "form_id": 1,
  "title": "Бланк №1 (Алгебра)",
  "questions": [
    {
      "number": 1,
      "type": "multiple_choice",
      "text": "Сколько будет $\\frac{3}{4} + \\frac{1}{4}$?",
      "correct_answer": "C",
      "options": [
        { "label": "A", "text": "1/2", "is_correct": false },
        { "label": "B", "text": "3/4", "is_correct": false },
        { "label": "C", "text": "1", "is_correct": true },
        { "label": "D", "text": "2", "is_correct": false }
      ]
    },
    {
      "number": 21,
      "type": "short_answer",
      "text": "Решите уравнение: $2x + 6 = 14$",
      "correct_answer": "4",
      "metadata": {
        "acceptedAlternates": ["4.0", "4,0"]
      }
    }
  ]
}
```

### Правила валидации:
1. В бланке должно быть **ровно 30 вопросов**.
2. Вопросы **1–20** должны быть типа `multiple_choice` и содержать **ровно 4 варианта** ответа (A, B, C, D).
3. Вопросы **21–30** должны быть типа `short_answer` и **не иметь вариантов** ответов.
